# 파생 수급 레이더 2.0

최근 5·15분 수급이 바뀌는지, 외국인 선물과 현물·프로그램·지수가 같은 방향인지 확인하는 로컬 프로그램입니다. 실제 보유 포지션을 알아내거나 매매 수익을 보장하는 프로그램은 아닙니다. 자동 주문 기능은 없습니다.

## 처음 실행

1. 압축을 **새 폴더**에 풉니다. 이전 프로그램의 데이터와 설정을 덮어쓰지 마세요.
2. `데모실행.bat`을 실행하면 약 1분 동안 가상 시장을 재생합니다. 일반 Python만 필요하며 API 키·키움 설치는 필요하지 않습니다.
3. 실제 데이터는 `0_설치.bat` → `연결설정.bat` → `실시간실행.bat` 순서입니다.
4. 화면은 `http://127.0.0.1:8765/`에서 열립니다. 실행창을 닫으면 수집이 종료됩니다.

데모와 실제 데이터는 `data_demo/`, `data/`로 분리됩니다. 두 실행 모드를 동시에 켜지 않습니다. 포트가 겹치면 기존 실행창을 종료하세요.

## 기존 키움 API 그대로 재사용

예전에 만든 `kiwoom-flow-radar-v1.zip`의 `entry_radar/kiwoom.py` 클라이언트를 `legacy_rest.py`로 재사용했습니다. 기존 OAuth 인증 방식과 키 변수명을 유지했습니다. 기존 앱은 변경하지 않습니다.

- `KIWOOM_APP_KEY`, `KIWOOM_SECRET_KEY`, `KIWOOM_USE_MOCK`을 지원합니다.
- 이전 이름인 `KIWOOM_APPKEY`, `KIWOOM_SECRETKEY`, `KIWOOM_ENV`도 지원합니다.
- `연결설정.bat`에서 기존 앱의 `.env` **파일 경로만 지정**하면 됩니다. 키를 새로 발급하거나 대화에 붙여넣을 필요가 없습니다. 키 파일을 복제하지 않습니다.
- 기존 앱의 `local_credentials.json`도 같은 방식으로 연결할 수 있습니다. 이 파일이 가리키는 기존 App Key·Secret Key 파일을 직접 읽으며 키를 새 파일에 복사하지 않습니다.
- 자동 탐색 순서: config.json의 `rest.env_file` → `KIWOOM_ENV_FILE` → 이 폴더의 `.env` → 옆 `kiwoom-flow-radar-v1/.env` → 상위 폴더 `.env`.
- 환경변수에 같은 키가 있으면 환경변수가 우선합니다.
- REST와 국내 파생 Open API+는 별도 인터페이스입니다. **REST App Key로 OCX 로그인을 대신할 수 없습니다.** 첨부된 1차 프로그램과 같은 `KHOPENAPI.KHOpenAPICtrl.1` 로그인 방식을 파생 수집에 유지했습니다.
- 파생 수집은 기존 Windows Open API+ 및 32비트 Python/PyQt5 환경을 사용합니다. 실행 경로가 다르면 연결설정에서 지정합니다. 기본은 기존 프로그램처럼 `py -3-32`입니다.

설치는 일반 Python에 `requests`, 32비트 Python에 `PyQt5`를 설치합니다. 기존 환경에 이미 있다면 재설치할 필요가 없습니다. 사용자 지정 32비트 경로를 쓸 경우 해당 실행 파일로 `-m pip install -r requirements_ocx.txt`를 실행하세요. UI·REST와 OCX는 별도 프로세스여서 대시보드 전체를 32비트로 실행할 필요가 없습니다.

## 화면을 매매에 활용하는 순서

1. **수신 상태**: 외국인 선물·프로그램·지수가 최신인지 먼저 확인합니다. 대시보드 생성 시각과 원자료 수신 시각은 다릅니다.
2. **최근 유입**: 당일 누적이 -3,000계약이어도 최근 5분 +500계약이면 매수 유입으로 표시합니다. 당일 0 돌파를 기다리지 않습니다.
3. **동조/엇갈림**: 선물 유입, 현물 또는 프로그램 유입, 지수 변화라는 세 묶음을 봅니다. 현물 수급과 프로그램을 독립된 두 표로 중복 가산하지 않습니다.
4. **종목 확인**: 관심종목 수급과 실제 가격·거래량을 HTS에서 확인합니다. 지수 방향을 개별 종목의 확정 신호로 바꾸지 않습니다.
5. **관측 결과**: 관측 시점과 기준값, 5·15·30·60분 뒤 지수 수익률을 기록합니다. 장중 용도이므로 익일 일봉 적중률만으로 평가하지 않습니다.

기본 관측 기준은 선물 최근 5분 ±300계약, 프로그램/현물 ±100억원, 지수 5분 ±0.08%, 동조 3분 지속, 같은 알림 15분 간격입니다. **이 수치는 초기 운영값이며 실증적으로 검증되거나 최적화된 기준이 아닙니다.** 설정과 실제 기록을 함께 비교하세요. 화면의 평균은 방향을 반영한 지수 변화이며 실제 포트폴리오 수익이 아닙니다.

선물 수급이 미연결이면 ‘현물 매수/매도 유입’으로 표시하고 파생 분석이 미완성임을 명시합니다. 데이터 중단이 있으면 그 항목의 시간차 분석과 지속 조건은 끊깁니다. 장외에는 신호를 생성하지 않습니다. 저장된 최근 거래일이 있으면 과거 관측으로 표시합니다.

## 투자자별 파생 TR 연결

연결 점검을 이어서 할 때는 기존 레이더 실행창을 닫고 `투자자수급점검.bat`을 실행합니다. 기존 32비트 실행 환경과 Open API+ 로그인을 사용해 설치된 공식 명세의 opt50038을 외국인·금융투자 각각 한 번만 조회합니다. 계좌조회·주문은 하지 않습니다.

키움 **버전처리** 안내가 나오면 실행기가 스스로 종료해 OCX·DLL 잠금을 풉니다. 검은 창에 그 안내가 표시되면 키움 팝업의 **[확인]** 을 누르세요. 업데이트 창이 닫히면 점검기나 수집기가 자동으로 다시 로그인합니다. 수집기와 점검기는 동시에 실행되지 않습니다.

결과는 `data/investor_probe.json`과 `data/투자자수급_연결점검.txt`에 저장됩니다. 현재 근월물 선물 코드와 정확히 일치하는 행의 순매매 수량이 있는지 확인하며, 옵션 수량을 선물 수량으로 바꾸거나 누락을 0으로 채우지 않습니다. 금융투자는 기관계 전체와 다릅니다. 결과가 있더라도 실제 지원·범위·단위를 검토하기 전에는 자동 판정에 넣지 않습니다.

일반 실시간 실행도 수급 매핑이 비어 있으면 같은 두 건의 점검을 로그인 후 한 번 수행합니다. 이 기능은 수급 연결의 검증 단계이며 전체 파생 포지션 자동 연결의 완료를 의미하지 않습니다.

1. Open API+ 로그인 후 화면 하단 ‘투자자별 파생 TR 연결’ → ‘설치된 TR 명세 보기’를 누릅니다.
2. 실제 설치된 .enc의 TR 이름, 입력 이름, 출력 레코드·필드를 확인합니다. 원래 프로그램처럼 `opt50008`을 투자자별 TR로 단정하지 않습니다.
3. KOA Studio/키움 도움말에서 **시장구분 enum, 당일/누적 구분, 단위**를 확인합니다. 파일 존재는 서버 지원의 증거가 아닙니다.
4. sources JSON을 입력하고 저장합니다. 모든 입력 이름과 출력 필드는 공식 .enc에 대조한 후 저장됩니다. 알 수 없는 enum을 자동 추정하지 않습니다.
5. `data/tr_result_소스ID.json`의 실제 응답 및 normalized values를 HTS와 대조합니다. 8초 응답 초과·빈값은 오류로 표시되며 이전 값은 TTL 이후 제외됩니다.

아래는 구조 설명용 예시입니다. 꺾쇠 항목을 **실제 확인한 값**으로 바꿔야 하며 TR 번호·필드명을 의미하는 예시는 아닙니다.

```json
[
  {
    "id": "futures_investors",
    "enabled": true,
    "trcode": "<실제 확인한 opt 코드>",
    "scope": "cumulative_day",
    "inputs": {"<정확한 입력 이름>": "<확인한 입력 값>"},
    "fields": {
      "foreign_fut_qty": {
        "record": "<출력 레코드>",
        "field": "<당일 순매매 계약 수>",
        "row": 0,
        "scale": 1
      },
      "inst_fut_qty": {
        "record": "<출력 레코드>",
        "field": "<기관 당일 순매매 계약 수>",
        "row": 0,
        "scale": 1
      }
    }
  }
]
```

여러 투자자가 행으로 나오는 TR은 `where: {"field":"<투자자 식별 필드>","equals":"<외국인 식별 값>"}`를 사용합니다. 매수/매도가 따로 있으면 `field`에 매수, `subtract`에 매도 필드를 지정합니다. 금액 환산은 원→억원 `0.00000001`, 천원→억원 `0.00001`, 백만원→억원 `0.01`, 억원→억원 `1`입니다. 계약 수에는 금액 환산을 적용하지 않습니다. 만기 이후 누적·보유량 추정치를 당일 수급으로 연결하면 안 됩니다.

TR 미지원 시에는 화면의 ‘HTS 수급 CSV 연결’에 `examples/flows.csv` 형식으로 입력합니다. asof는 실제 한국시간이며 현재 날짜만 허용합니다. 최신 행 한 개를 읽으므로 반복 업로드는 **새 수신 시각의 실제 관측**이어야 합니다. 오래된 CSV를 현재 시각으로 바꿔 재활용하지 마세요.

## 추정 옵션 포지션

`examples/positions.csv` 형식으로 증권사에서 확인한 추정 보유량과 단가를 넣고 ‘추정 포지션 CSV 연결’을 누릅니다. 예시 파일의 숫자는 가상입니다.

- 정규 KOSPI200 선물·옵션만 지원합니다. `product` 열 생략 시 KOSPI200으로 간주하며 미니·개별주식 파생은 지원하지 않습니다.
- `net_qty`: 추정 보유량, 매수 양수·매도 음수. 당일 매매량을 넣지 않습니다.
- `avg_price`: 추정 보유단가, 포인트 단위.
- `delta`: 옵션 1계약 기준 콜 0~1, 풋 -1~0. 매도 포지션의 부호는 net_qty가 반영합니다.
- `expiry`: 실제 만기일 YYYY-MM-DD. 다른 만기는 같은 손익곡선으로 합치지 않습니다.
- `asof`: 동일 투자자·동일 만기의 모든 행은 같은 관측 시각이어야 합니다.
- `scope`: 반드시 `broker_estimate`. 순매매 누적을 보유량으로 취급하지 않습니다.

만기손익은 계약당 250,000원 승수로 계산한 옵션 내재가치/선물 정산가와 추정 매입단가의 차이입니다. 표시 지수 구간 ±8%는 보기 위한 범위입니다. 델타는 현재 지수 부근 노출의 추정이고 실제 향후 손익·매매 목적과 다를 수 있습니다. 현재 내재변동성·미결제 분포는 추정 포지션을 복원하는 데 사용하지 않습니다.

## 저장·검증

- `data/radar.sqlite3`: 분 단위 관측, 이벤트, 실제 REST 응답, 일별 마지막 관측.
- `data/daily.csv`: 일별 마지막 관측의 내보내기. 거래소 확정치로 자동 보정되지 않으며 `finalized=false`입니다.
- `data/latest.json`: 마지막 화면 데이터. 원자료 시각이 포함됩니다.
- `data/tr_catalog.json`: 현재 설치된 공식 TR 정의 목록.
- `data/tr_result_*.json`: 연결한 TR의 실제 응답과 변환값.
- 화면의 ‘기록 CSV 내보내기’: 이벤트와 5·15·30·60분 뒤 결과.

만기 누적은 시작일부터 빠진 거래일을 확인하며, 누락이 있으면 ‘부분 누적’으로 표시합니다. 주말·설정된 휴장일은 제외합니다. 2026년 휴장일 설정에는 6월 3일·7월 17일을 포함했습니다. 임시 휴장·새 연도는 거래소 일정과 대조해 갱신하세요. 위클리 옵션은 별도 상품 연결을 구현하지 않았으며 월물 옵션 분포와 혼합하지 않습니다.
