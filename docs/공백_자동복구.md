# 공백 과거 자료 복구 — 2026-10-30

## 역할과 저장

`gap_recovery.py`는 중간 접속·절전 복귀 뒤의 누락 분과 누락 주요 필드를 확인한다. 완료되지 않은 최근2분은 제외한다. 조회한 값은 `data/gap_recovery.sqlite3`에만 저장하고 `radar.sqlite3`의 ticks/events/daily 및 Engine.history/values에는 넣지 않는다. 따라서 복구된 자료로 당시 반등 신호를 새로 만들거나 실시간 구간 계산의 공백을 숨기지 않는다.

기존 유효한 실시간 값(0포함)은 보존한다. 일부 필드만 비거나 오래된 분에는 분석용 자료를 별도 보충한다. 원본 DB는 SQLite backup API로 첫 복구 전 일별 백업한다. 현재 복구 기능은 원본 실시간 DB와 마감 요약을 수정하지 않는다.

보충 자료에는 backfilled=true, provenance=recovered, LS 사후 조회 품질, 실제 원자료 시각, 조회 시각, 상품코드, 출처·범위를 남긴다. 없는 수급을 시간에 따라 균등 배분하거나 시세로 미결제를 추정하지 않는다. 날짜가 달라진 조회나 다른 선물코드의 연결은 차단한다.

## 자동·수동 실행

실시간 앱이 시작되면 원래 LS 수집기의 토큰과 TR별 호출 간격을 공유하는 복구 작업 흐름을 시작한다. 실시간 수집과 분리된 작업 흐름이며 복구 DB 오류가 나도 실시간 수집은 계속된다. 자동 확인은 장중에 로컬 기록을 확인하며, 미완료 구간별 자동 시도는 최대3회·하루 자동 복구 작업 최대12회다. 한 작업은 최대48회 요청·3분이며, 절전·거래일 변경 등으로 넘으면 받은 부분까지만 보존하고 상태를 표시한다. 이미 보충된 필드는 대상에서 제외한다.

앱의 ‘끊긴 구간 · 과거 자료 복구’에서 ‘오늘 누락 자료 복구’를 눌러 다시 요청할 수 있다. ‘복구 범위·지표별 자료 수’에서 작업별 추가 값·주요 지표 미확보·조회 오류를 확인할 수 있다. 원자료 CSV는 /api/recovery.csv다.

단독 도구는 `python ls_backfill.py 2026-10-30 --start 11:53 --end 12:29`처럼 구간을 지정할 수 있다. `--dry-run`도 실제 API 조회를 하지만 복구 DB에는 저장하지 않는다. 앱 실행 중에는 토큰과 호출 간격을 공유하는 앱 버튼을 우선 사용한다.

## 범위와 차트

LS t8465 선물1분봉(가격·미결제), t8409 KOSPI2001분봉, t1602 투자자 시간대 수급, t1662 프로그램을 재사용한다. 당일/전일 수급 제공 범위와 실제 응답에 따라 부분 복구일 수 있다. 날짜 지정 가능한 분봉도 현재 코드와 이력 상품코드의 호환성을 확인한다.

선물·지수·프로그램·미결제 차트에서 사후 보충 구간은 점선으로 표시한다. 원래 실시간 선은 그대로라 당시 수집 공백은 보존된다. 듀얼축의 원본·복구 계열은 같은 축 범위를 공유한다.

2026-10-30 그래프 연결 보완: 상단 ‘외국인 장중 흐름’은 한투의 미니 포함 선물 합계·옵션 합계로 별도 계산되므로 기존 복구 선이 연결되지 않았다. 이제 한투 선물 합계가 없는 분에는 LS 일반선물 사후 조회값을 독립적인 보라색 점선·점으로 표시한다. 일반선물을 미니 포함 합계로 치환하거나 옵션으로 사용하지 않는다. 원래 합계·옵션의 공백은 남으며 화면에 미복구임을 명시한다. 다른 거래일·원래 차트 범위 밖 자료를 끌어오지 않고 유효한 원본 0도 보존한다. 단독 복구 분은 M 경로만으로 보이지 않는 문제를 고쳐 점으로 표시한다. 복구 패널에서 상단·선물지수 차트로 바로 이동할 수 있다.

이 표시 수정은 원자료를 새로 조회하거나 원본 DB·반등 판정을 변경하지 않는다. 전체 Python 검사271개(32비트 전용1개 제외, 실패0), 그 안에서 실제 차트 그리기 코드의 JavaScript 재현 검사6개를 실행했다. 오늘 실제 자료를 넣은 화면에서 상단36분 참고값과 하단 복구 점 표시를 확인했다.

## 앱 재시작 뒤 버튼 인증 복구

기존 화면은 최초 접속 때 받은 로컬 세션값을 계속 사용하므로 앱이 재시작되면 버튼이 ‘인증 실패’로 끝났다. 이제 세션 불일치는 작업 실행 전에401/session_expired로 구분한다. 화면은 기존 로컬 bootstrap으로 세션을 갱신하고 같은 요청을 최대1회만 다시 보낸다. 초기 화면 로딩 중 클릭도 세션 준비를 기다린다. 외부 출처 차단·미리보기 입력 차단은 유지하고, 네트워크 응답이 불확실하거나 일반 작업 오류이면 재전송하지 않는다. 증권사 키·인증 파일·설정은 변경하지 않는다.

LS 현물은 KRX 범위로 `_spot_krx_amt` 필드에 별도 저장·표시한다. 기존 KRX+NXT 현물의 대체값으로 합치지 않는다. 이론 베이시스와 시장−이론 베이시스의 당시 값을 이번 과거 조회로 만들지 않는다. 첫 분봉 완성 전 시각·개장 전 프로그램 등 API에 값이 없는 항목도 추정하지 않는다.
